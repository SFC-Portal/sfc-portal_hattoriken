# /simplify - コードレビュー＆簡素化

このコマンドは、コードをレビューして簡素化・改善点を提案します。

## 実行手順

### 1. 変更ファイルの取得

```bash
git diff --name-only HEAD~1
```

または指定されたファイルを確認。

### 2. レビューチェックリスト

各ファイルに対して以下をチェック：

#### コード品質

- [ ] **不要なコード** — 使用されていない変数・関数・インポートはないか
- [ ] **重複コード** — 同じロジックが繰り返されていないか
- [ ] **複雑な条件分岐** — 簡素化できるif文やswitch文はないか
- [ ] **長すぎる関数** — 1つの関数が多くのことをしていないか（50行以上は要注意）
- [ ] **ネストが深い** — 3段階以上のネストは早期リターンで解消できないか

#### プロジェクト規約

- [ ] **ブランチ名** — `{名前}/{機能}/{変更}` 形式になっているか
- [ ] **ファイル配置** — 正しいディレクトリに配置されているか
- [ ] **命名規則** — PascalCase（コンポーネント）、camelCase（関数）に従っているか
- [ ] **コメント形式** — `// === セクション名 ===` 形式になっているか
- [ ] **インポート順序** — 外部ライブラリ → 内部モジュールの順か
- [ ] **200行制限** — コンポーネントが200行を超えていないか

#### TypeScript

- [ ] **any型** — `any` を使用していないか
- [ ] **型定義** — 適切な型が定義されているか
- [ ] **strictモード** — 型エラーがないか

#### セキュリティ

- [ ] **機密情報** — APIキー、パスワードがハードコードされていないか
- [ ] **入力検証** — ユーザー入力は適切にバリデーションされているか

### 3. 出力フォーマット

```markdown
## レビュー結果

### 📁 {ファイル名}

#### 問題点

1. **{問題の種類}** (行 {N})
   - 現状: {現在のコード}
   - 提案: {改善後のコード}
   - 理由: {なぜ改善すべきか}

#### 簡素化の提案

1. **{提案タイトル}**
   ```typescript
   // Before
   {現在のコード}

   // After
   {改善後のコード}
   ```

### ✅ 良い点

- {良かった点を列挙}

### 📊 サマリー

| 項目 | 状態 |
|-----|------|
| コード品質 | ✅ / ⚠️ / ❌ |
| 規約準拠 | ✅ / ⚠️ / ❌ |
| TypeScript | ✅ / ⚠️ / ❌ |
| セキュリティ | ✅ / ⚠️ / ❌ |
```

### 4. 自動修正

軽微な問題（インポート順序、未使用インポートなど）は、ユーザーの許可を得て自動修正を提案。

```text
以下の問題を自動修正できます：
1. 未使用インポートの削除 (3件)
2. インポート順序の整理 (2件)

自動修正を実行しますか？
```

## 使用例

```text
ユーザー: /simplify
Claude: 最新のコミットの変更をレビューします...

ユーザー: /simplify frontend/src/components/tasks/TaskCard.tsx
Claude: 指定されたファイルをレビューします...

ユーザー: /simplify --all
Claude: ステージングされた全ファイルをレビューします...
```
